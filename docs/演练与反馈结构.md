# 演练与反馈结构笔记

这份笔记保留目前整理出的功能流程和字段定义。日常对话已有测试输出；本节尚无完整的“实际演练对话 + 对应报告”样本，因此不把字段整理等同于评分逻辑已验证。

## 场景演练

任务链：角色资料 → 场景选择 → 开场语 → 多轮练习 → 生成报告 → 等待完成 → 展示反馈。

角色资料涉及 relation、sex、callName、nameCall、catchphrase、voice、painPoint[]、requests[]，分别对应关系、性别、双方称呼、口头禅、语音、痛点和诉求。演练与报告应分开处理，不能把日常聊天提示词直接当作评分量表。

## 报告字段

| 字段 | 展示用途 |
|---|---|
| date / title | 日期与场景标题 |
| boundaryGuardScore | 边界守护力，页面按百分制展示 |
| coreAbilities[] | 核心能力，包含 dimension 和 score |
| performance | 整体表现 |
| strengths[] | 做得好的点 |
| improvements[] | 待改进点 |
| dialogueOptimization | 话术优化 |
| advancedSuggestion | 进阶建议 |
| closingSlogan | 收尾语 |

维度名称、数量、权重与计算公式仍未确定。展示分数和进度条不意味着客户端计算了分数，也不能从页面装饰推定固定维度数量。

独立实现时，应先定义可审查的量表版本，再让评语引用本轮具体发言。报告里的行为不能凭空编造；评分要能与采用的量表对照。当前没有独立实现评分器。

## 话术助手及其他反馈

话术助手的输入为对方的问题与用户诉求；结果包含 breakthrough_point，以及 strategies 数组中的 title、style、content、game_point。分别呈现突破点、策略标题、风格、可发送正文和策略解释。数组长度不等于固定策略数。

周洞察涉及 reportTime、summary、reports、radarData；心灵解码涉及 type、declaration、reports。具体总结窗口、题目权重与分类依据尚未确认。

下一步应以正常使用得到的完整样例校准，而不是根据字段名称编造原算法。
