围绕关系沟通与咨询式回答，整理课程文本、同题对话样本，以及可直接使用的独立角色提示词。重点关注如何判断投入变化、解释互动责任、给出具体行动，并在新事实出现后修正建议。

## 从这里开始

1. 打开 [v0.3 角色提示词](prompts/v0.3/system.txt)，将全文放入自己模型的 system 消息。
2. 按顺序加入当前会话的 user / assistant 历史，再加入本轮问题。
3. 参考 [风格示例](prompts/v0.3/examples.md) 理解目标表达；示例是人工编写，不是模型测试成绩。
4. 需要课程材料时，在 [课程目录](courses/README.md) 找到正文；引用时注明课程名，并核对上下文。

本仓库是资料与设计集合，暂不包含可运行的聊天网站、模型凭证或服务端部署程序。

## 提示词的设计方向

v0.3 将回答组织为：**先判断核心矛盾 → 用行为事实解释 → 给一个主要策略 → 说明下一步观察点**。遇到足以改变判断的新事实，明确撤回旧建议；只要一句回复时，就只给一句可发送的话。

三个形象在当前样本中使用相同的可见文本角色配置，回答的核心策略接近。本项目采用一个文本角色配合不同外观的设计，不据此宣称所有后台设置完全相同。

这里的角色提示词由本项目独立编写，不是原产品官方系统提示词，也不代表课程讲授者本人。课程资料是参考材料；目前没有证据表明测试产品使用了这些课程作为知识库。

## 状态与使用范围

- 课程文本可能存在转写错误或缺段，原有完整性提示予以保留。
- 对话记录来自主动构造的虚构测试，不是个人情感咨询记录；连续对话首轮与同题 A 样本重复，共六份不同的输出。
- 提示词尚未完成自建模型 A/B 测试，具体模型、参数和上下文都会影响回答效果。
- 课程正文保留原课程归属；本仓库不以统一开源许可证替第三方材料授予使用许可。

## 本地文件核验

使用 Python 3.10 或更新版本，在仓库根目录执行：

```bash
python scripts/verify_publication.py
```

该命令核对课程清单、文件摘要、内部文档链接和发布文件类型；不调用模型，不验证课程完整性或回答质量。
